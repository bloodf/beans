### Decision and boundaries

Select E2E-encrypted binary WebSocket forwarding through an operator's self-hosted relay, with independent baseline JPEG frames. Runner and viewing Device cores each make outbound WSS connections; no inbound phone/Runner port, STUN, TURN, public VNC or public SPICE. Separate control and frame sockets share one authenticated session, avoiding frame backlog on the input socket; both use the same transport. TCP head-of-line stalls remain possible. This choice favors universal JPEG decoding and outbound connectivity over video efficiency; WAN performance is unproven. TLS verification is mandatory; failed proxy traversal means unavailable, not plaintext/direct fallback.

Reject direct Device-to-Runner WSS as sole transport: inbound reachability/CGNAT and certificates are unresolved. Reject WebRTC for this contract: better congestion/media handling, but ICE/TURN operations, headless encoding and WebKitGTK/native mobile integration remain unverified. Reject raw VNC/SPICE exposure and chat blobs: private hypervisor protocols are not Device authorization, and stored sync traffic has wrong latency, retention and quotas. These are design comparisons, not comparative benchmarks.

Scope: self-hosted Linux guests only; QEMU/KVM/libvirt remains a candidate pending feasibility evidence. No containers or host-execution fallback. Runner remains the always-available agent/control plane. Guest receives scoped display/input capabilities, never master keys, account DEK, full provider credentials, relay storage or host filesystem mounts. Stop preserves disks, not RAM/application state; owned-server and retained-disk costs continue. No billing or usage metering is introduced.

### Authority and session keys

Issue #34 owns proposed `computer-ownership.md`: bot/Runner authority, config/status, operation admission and revocation. That interface is a reconciliation target, not an implementation dependency. Each envelope binds `account`, `bot_id`, `runner_id`, `requester_device`, `computer_generation`, `policy_revision`, lifecycle fencing `epoch`, random 128-bit `session_id`, mode, expiry and negotiated version. Generation distinguishes guest incarnations; epoch fences lifecycle/ownership transitions within one incarnation. The authority owner supplies both; neither relay nor viewer invents them. Pause/revocation invalidate grants and queued input. A mandatory new computer-capable protocol floor and fail-closed authenticated capability admission precede grant issuance; this is NOT additive protocol 5. Unsupported/old clients receive no control grants. Exact floor allocation stays with #34.

Proposed open request is a signed existing-style sealed request to the Runner, domain `beans-display-open-v1`, binding that tuple, requested `view`/`control`, fresh challenge and ephemeral X25519 public key. Runner verifies current membership, Device signature and current ownership/policy/lifecycle before replying, sealed to that Device's attested box key. Signed reply binds the complete request hash, Runner ephemeral key, chosen limits, granted mode and ≤30-second single-use rendezvous ticket. Viewer verifies Runner membership/key and signature. Both sign deterministic fixed-order JSON arrays (UTF-8; integer versions/counters; canonical unpadded base64url keys); unsupported fields/version reject, not reinterpret. A relay bearer alone never authorizes viewing or control.

Derive fresh directional AES-256-GCM keys using X25519 and HKDF-SHA256, transcript SHA-256 as salt and distinct `beans-display-v1/{control,frames}/{sender}` info strings. Reject invalid/all-zero DH; require encrypted transcript confirmation before frames/input. Never derive session keys from the account DEK or send them to the relay/guest. Nonce is four zero bytes plus big-endian u64 record sequence, starting at zero separately per directional key. Never reuse keys on reconnect; close before counter wrap or after one hour. Delete ephemeral secrets on close. Signatures bind ephemeral keys to long-lived Device keys; bearer theft alone cannot impersonate endpoints. This handshake needs independent cryptographic review before implementation.

### Proposed wire and input

Proposed `/v1/display` rendezvous is a NEW nonpersistent forwarding route, not `/v1/sync`. Authenticate each core using Device bearer plus computer-capability admission; consume the short-lived ticket on binding the socket pair, not from a logged URL. No bearer/ticket in query strings. Relay pairs only same-account tickets for the specified endpoints; endpoint confirmation still authenticates peer. A viewer core owns keys/network, presenting decoded bytes to AppKit, the local desktop bridge or phone native surface; web content receives no Device secrets. Local bridge admission remains scoped to the active account/viewer and exact trusted origin.

One binary WS message = `version:u8=1 | channel:u8 (0 control,1 frames) | sequence:u64be | ciphertext_length:u32be | ciphertext | tag:16`. Authenticate the 14-byte header plus transcript hash as AAD. Bound message before allocation: control ≤64 KiB plaintext, frame ≤1 MiB. Enforce expected channel, exact next sequence and lengths; malformed, replayed, wrong-session or failed-tag records close. No compression extension. Encrypted control body is closed-schema UTF-8 JSON `{type, body}`; frame plaintext is `frame_id:u64be | capture_monotonic_us:u64be | width:u16be | height:u16be | JPEG`. Dimensions ≤1920×1080, baseline 8-bit sRGB JPEG, no EXIF/ICC/private metadata. Validate decoded dimensions/pixel count before allocation; each frame is independently decodable. Capture timestamps are Runner-relative, not cross-device latency proof. Resize negotiates dimensions; no partial-frame stitching.

Control types: `ready`, `configure`, `input`, `ack`, `ping`, `pong`, `release`, `closed`. Every input carries increasing `input_id`, grant id, epoch/generation/policy revision and latest displayed `frame_id`. Runner checks live authority immediately before injection, not only socket open; reject stale tuples, duplicates, events older than 250 ms by Runner-issued challenge timing, or frame references older than two seconds. Ack means injected/rejected with stable reason, not application completion. Never replay unacked input after reconnect.

Pointer events use absolute unsigned 0–65535 guest coordinates, explicit button down/up and signed wheel deltas in pixels; map only inside letterboxed content. Keyboard uses USB HID usage plus down/up, not platform virtual-key codes; explicit UTF-8 text commit handles IME (≤4 KiB/event), never duplicate HID text. Track pressed keys/buttons and release all on focus loss, disconnect or ownership loss. Touch maps one contact to pointer; tap clicks, two-finger motion scrolls; pinch zooms locally, never injects multiple guest contacts. Host-reserved shortcuts remain local unless explicit capture is enabled, with a visible escape action. Reject unsupported usages, invalid coordinates and malformed UTF-8 before injection.

Clipboard defaults off both directions. Explicit per-session consent permits user-initiated UTF-8 text only (≤64 KiB); no files, rich content or background synchronization. View-only grants reject clipboard writes and every input even if UI sends them. `sensitive:true` accompanies text/key/clipboard events when the user enables sensitive entry; no payload logging, recording or clipboard persistence, and buffers clear on ack/close. Marker is an advisory handling label, not guest password-field detection or protection from the guest/Runner. Frames may still contain secrets.

### Fencing, leases and resource policy

View grants allow frames/status/heartbeat only; control requires the authority owner's exclusive lease shared with bot/controller actions, never a second transport-owned lock. Proposed control lease: ten seconds, renewed every three seconds only after current policy/membership/epoch recheck. Encrypted heartbeat every three seconds; no valid pong/renewal for ten seconds revokes control and releases pressed state. Pause, unpair, stop, restart, deletion, reassignment or generation/epoch/policy change invalidate grants, clear frame/input queues and close sockets before further injection. Partitioned authority cannot renew; offline control is forbidden. Runner restart invalidates all process-local sessions. Lease expiry must release guest key state even when network is gone.

Disconnect does not stop the guest or roll back injected actions. Reconnect uses fresh auth, ticket, ephemeral keys, session and lease; starts view-only with a fresh complete frame. Control reacquisition is explicit. Close reasons distinguish unsupported capability, denied, stale fence, revoked, timeout, quota and unavailable without private endpoint details. Retain no frame/input outbox or recordings.

Targets, NOT measured acceptance: 1280×720 at 15 fps, p95 capture-to-present ≤200 ms and input-to-visible-response ≤250 ms on RTT ≤80 ms, ≤1% loss and ≥8 Mbit/s usable path. Default frame budget 8 Mbit/s/viewer, hard 12; adaptive scale/quality/fps down to 640×360 at 5 fps. If unable to stay bounded, show degraded/unavailable, never queue stale frames. Keep one unsent latest frame; bound socket pending ciphertext to 2 MiB and close a viewer stalled two seconds. Control limits: 200 events/s, burst 400; coalesce pointer motion only, never key/button transitions. Defaults: two viewers and one controller per guest, four sessions/account; operator may lower. These are proposed fairness/safety limits, not stored-byte quotas or billing. Display bytes never enter blob/file storage; separate forwarding byte-rate/concurrency limits preserve chat's existing quota/rate bucket. Relay enforces encrypted byte/message limits and admission; Runner enforces plaintext semantics. No forwarding capability means display unavailable.

Hypervisor candidate: headless guest virtual display and input through VNC over a private Unix socket with directory 0700/socket 0600, readable only by hypervisor and scoped Runner adapter. If socket support fails, fail unavailable, not wildcard TCP. SPICE is not selected. Libvirt control socket stays privileged/private; no endpoint address, arbitrary connect URL or host path is client-supplied. Runner alone captures/encodes/injects. Guest-to-adapter graphics and input are plaintext inside the trusted host boundary; a host administrator or compromised Runner can observe them.

### Client and licensing feasibility

Analysis only, no mounted viewer proof: AppKit can decode JPEG with ImageIO and draw in an NSView; WebView2/WebKitGTK can decode JPEG images and draw canvas via the local bridge, without WebCodecs or H.264 assumptions. React Native requires a bounded native image/surface bridge from the Rust core (ImageIO on iOS, Bitmap decoding on Android), not per-frame base64 JSON through UniFFI events. Current phone start/request/wake API is not that bridge. All require actual decode/render/input and memory tests. Headless Runner uses guest framebuffer, not a host desktop/screen-capture permission. No audio is in scope.

WebSocket is [RFC 6455](https://www.rfc-editor.org/rfc/rfc6455); no codec license comes from choosing it. JPEG candidate implementation [libjpeg-turbo licenses](https://github.com/libjpeg-turbo/libjpeg-turbo/blob/main/LICENSE.md) require IJG/BSD notices (SIMD includes zlib terms); native OS decoders carry platform terms. Distribution must preserve notices and verify the pinned build; patent clearance is not asserted. Rejected WebRTC candidate libwebrtc is BSD-style with third-party notices; VP8/libvpx is BSD-style with patent grant terms, H.264/OpenH264 is BSD-style but binary patent arrangements do not blanket-cover source builds, and AV1/libaom uses BSD/patent terms. AppKit would need media integration; WebView2 commonly has WebRTC/H.264/VP8 while WebKitGTK depends on runtime/GStreamer builds; RN needs native WebRTC bindings. None of those video combinations is verified here. Do not copy FSL-1.1-ALv2 bops or PolyForm Noncommercial openbot code; Beans remains GPL-3.0.

### Evidence, disclosure and remaining acceptance

Measured 2026-10-14 on arm64 macOS 26.6.2, Bun 1.4.2, FFmpeg 9.0.2: `ffmpeg -v error -f lavfi -i testsrc2=size=1280x720:rate=15 -frames:v 150 -c:v mjpeg -q:v 5 -f image2pipe pipe:1` generated 150 JPEGs, 7,270,454 bytes. A throwaway loopback Bun WS sender/receiver used fresh Ed25519/X25519/HKDF-SHA256 and AES-256-GCM with signed fixture transcript as AAD; decrypted frames matched byte-for-byte. Packets (12-byte nonce + 16-byte tag + JPEG) totaled 7,274,654 bytes: 5.8197232 Mbit/s at nominal 15 fps. Sequential send/encrypt/ack p50 0.50275 ms, p95 2.615708 ms; decrypt p95 0.220583 ms. Anonymous HTTP returned 401; foreign signing key verification failed. Bun's attempted ChaCha cipher returned `Unknown cipher`; AES-GCM was measured instead. This supports framing cost and JPEG bandwidth choice only: no pacing, TLS, forwarding relay, production wire header, admission/lease implementation, viewer decode or guest was exercised. Fixture header authorization is NOT production Device authentication. Reproduce using ephemeral keys, sequential nonce counters and per-frame ack timing; report raw results separately from targets.

Privacy: relay sees authenticated account/Device public keys, endpoints' network metadata, tickets, session timing, lengths and rates; not decrypted frames/input. No claim hides traffic analysis. Plaintext exists in guest, private host graphics path, trusted Runner/core and authorized viewer memory/display; the host owner and endpoint malware can see it. Relay can deny/delay traffic, but cannot create valid signed/AEAD sessions. TLS alone would not be zero-knowledge; end-to-end keys are essential. No frames leave the trusted host unencrypted; no private endpoints or secrets belong in logs or published evidence.

Acceptance remains OPEN: chosen transport and complete proposed wire/privacy/feasibility analysis are recorded, but the required throwaway Linux KVM guest test-pattern stream to AppKit, WebKitGTK, WebView2 and iOS/Android phone/tablet prototypes, unauthenticated viewer denial, capture-to-present/input latency, sustained fps/bandwidth, NAT/mobile suspension, leases/revocation and loss/congestion behavior have no measured proof. QEMU 11.1.2 is available locally; libvirt/virsh and a Linux KVM host/guest are not admitted, and foreign-platform viewers are unavailable in this pass. Synthetic loopback is not that manual scenario. No Cargo/build/deployment/public exposure is authorized. Documentation check is `bun run check:docs`; its receipt accompanies the local commit.
