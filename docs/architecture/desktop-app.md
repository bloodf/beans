# Windows and Linux app

`desktop/` is the app for Windows and Linux, built with [MyGo](https://github.com/egoist/mygo): a Go process that owns the windows, the menu bars, the tray icon, notifications, and the CLI, and pages in the system webview (WebView2 on Windows, WebKitGTK on Linux) written with Solid 2 and TypeScript. It follows the macOS app screen for screen: the same windows, panes, sheets, menus, and words, with Lucide icons standing in for SF Symbols (`src/ui/icons.tsx` maps each symbol name the models and views use).

- **The Go side** (`desktop/*.go`): `launcher.go` finds the CLI (`BEANS_CLI`, the app's `resources/bin`, `~/.local/bin`, `~/.cargo/bin`, then `PATH`), admits only this build's fixed port (4874 production, 4875 Dev) before probing, and starts `beans serve --port … --parent-pid … --ready-stdout` when nothing answers, restarting it with the macOS launcher's backoff; `client.go` holds the one websocket to the CLI and reconnects it. Saved preferences and explicit `BEANS_PORT` must independently match the build; invalid configuration stays offline before probing, dialing, preference writes or reconnect. This is app connection policy, not a restriction on standalone CLI operator commands. A page calls the CLI through the bound `CLI.request` and hears its events as `cli:event`. `app.go` picks the window as the macOS AppDelegate does: onboarding until the CLI reports an identity, then the main window, and while onboarding is up, Settings as a small window of General and Advanced. A computer without an identity waits for the CLI's answer past the 2.5-second loading deadline, which a CLI's first start (a new binary, a new database) can outlast; a startup failure or 10 seconds without an answer opens the main window on the offline recovery controls. With a tray icon, closing the windows leaves the app running, since the bots on this computer run with it. `files.go` serves attachments and bot images to the pages by token under the `beans-file` scheme, and `avatar.go` makes a bot's image a square PNG of at most 512 px; `prefs.go` keeps the preferences (selection, pane widths, appearance, language, send key, the CLI port) in `preferences-v2.json` in the app's data folder; `menus.go` builds each window's menu bar from what the page describes and brings clicks back as commands. `Host.OpenExternal` opens only http(s) links with a host and mailto links, as the macOS app's `NSWorkspace.openLink` does, since links from bots, plugins, and the marketplace reach it.
- **The page** (`desktop/src`): `model/` is the macOS app's AppStore, models, formatters, and demo reply engine (`BEANS_MOCK=1`, or `?mock=1` in a browser tab) in TypeScript, and message Markdown is markdown-it folded into the blocks `crates/markdown` produces, with bare links found by the crate's autolink rules (`model/autolink.ts`). The store is plain and synchronous; `model/reactive.ts` turns its events into signals the views read. Routes (`@solidjs/router`) name each window's page: the main window at `/`, a chat at `/chat/:id` and a settings pane at `/settings/:pane` inside it, onboarding at `/onboarding`, and the small settings window at `/settings-window`. A selection replaces the route, and back and forward walk the settings panes, as the macOS toolbar's do. A sheet (`src/ui/overlay.tsx`) is the key window, as on the Mac: the window behind it is `inert`, keys typed while nothing has focus go to the sheet in front, and closing one hands the keyboard back to what had it. The composer has no Dictate button and General no Dictation section: WebView2 and WebKitGTK give a page no speech recognizer.
- **Bot avatars** (`src/ui/avatar.tsx`): `@beans/blobatar` generates a self-contained SVG from the stable bot id, encoded as an image URL rather than injected as markup. This works offline and matches the Mac and phone look for the same id. An encrypted uploaded profile image overrides it after local fetch; working dots, group clusters, and separate you/system discs remain. Marketplace bot previews use template ids (or names when an id is absent). The Look sheet drafts generated base appearance and per-activity-state settings independently of the uploaded photo. Save awaits one `bots.update` for changed look/photo fields; failures keep the draft open and show the error. See [Bot avatars](avatars.md) for the shared appearance contract. Legacy `symbol_name` and `accent` remain on the wire for compatibility but never render as bot avatars.
- **Provider models**: Settings › Providers offers Refresh Models for saved custom providers. It calls the CLI's `providers.refresh` and reports changed, unchanged, or error without exposing the key; newly discovered IDs appear in model pickers while the bot's selected model stays put.
- **MCP servers**: Settings › Plugins lists the picked Runner's marketplace plugins separately from its `mcp.json` servers. The Solid sheet adds, edits, parses pasted server JSON, enables, reconnects, signs out, hides individual tools, and removes a server through the CLI's `mcp.*` requests; sign-in uses `plugins.connect` so the browser opens on the requesting Device. The Runner owns its file and credentials. Reload rereads an externally edited file; Open is local to that Runner. The inspector opens the same sheet for a Runner-owned server, while bot capability switches still limit each bot's plugin access.
- **Memory service models**: the isolated request/draft adapter and local-editor boundary are described in [Memory service UI](memory-ui.md).

The Solid chat composer awaits `chats.send` acknowledgement through ChatView and the store. Text, files, picked mentions and reply remain editable while the submitted draft is pending; another send is refused. An acknowledgement naming the submitted message clears only an unchanged draft revision, so edits made while waiting survive. Refusal or an unconfirmed response retains the draft and removes only the local optimistic placeholder, never a row replaced by a CLI event. The transport does not distinguish API rejection from a lost response: the composer reports an unconfirmed send, asks the user to check the chat before sending again, and never retries automatically. Admission acknowledgement does not mean that the Runner has finished the turn.

Solid drafts retain one owner per account identity and chat across chat selection and Settings unmount/remount. Pending submission and draft revision belong to that retained owner, not the mounted component; completion updates the owner even while Settings is open. Other-account unsent intent remains in page-memory recovery and returns only when that account and chat are selected again. Account or connection transitions invalidate pending acknowledgements, retaining uncertainty instead of clearing intent. Store completion and its working-placeholder timeout bind to the captured account, bootstrap generation and exact pending job object; a late completion cannot remove another submission's work. Send completion never redirects chat selection.

The opt-in native memory panel includes embedding-profile Add/Edit/Remove controls with complete API/local-CPU vector-space inputs and explicit secret changes. Profile drafts share memory mutation admission, pending/error retention and account-keyed recovery; the working full client remains the default.

The native panel also offers each bot's MEMORY.md editor through existing Runner-routed calls, explicit hash-bound Save and confirmed conflict recovery. File size is bounded independently of the per-turn loading budget; note intent shares native close/quit guards and account-separated recovery.

The native note language bridge uses the existing selected language and system locale for English/Simplified Chinese. Preference changes invalidate the native window; note error keys remain language-neutral until rendering so changing language does not discard or rebase a draft. This scope does not establish whole-native localization parity.

The host admits account state through `model.Session` on an ordered main-thread dispatch queue (`dispatch.go`). A new connection requests `bootstrap`; live events wait behind its snapshot. Disconnect invalidates pending bootstrap completions. Identity loss bypasses the buffer, clears queued account events and prevents the earlier bootstrap from restoring the account. Websocket frames from a previous connection cannot complete current requests or reach account consumers. The Solid page remains the working client, including the website's shared offline preview, memory sheets and Blobatar renderer.

`BEANS_NATIVE=1` additionally opens a MyGo native-content window using the endpoint toolkit revision `e6cb2f146f33`. `native.go` renders the sidebar, admitted transcript and multiline composer without a webview. `model.NativeStore` consumes the same `Session` events and sends through the host's existing CLI connection. Text, file, mention and reply drafts remain until an awaited send succeeds. Every connection transition closes native presentation/mutation admission until an authoritative snapshot supplies the account identity ID. A same-account reconnect preserves drafts; a different account or identity loss retains unsent intent in account-keyed recovery storage, never in the new account's composer. Native requests capture socket generation and account authority before asynchronous dispatch; the client checks both under its write lock, so a replaced authority cannot receive an old payload. Connection/account epochs also fence send, paging and file-picker completions. Running-turn events drive Stop; explicit older-page loading deduplicates messages and rejects stale completions.

The native sidebar binds each chat row's selected presentation and accessibility state to `NativeStore.Selected` during rendering, including the first admitted frame. The transcript reads the same selection. `Session.Bootstrap` rejects prior connection generations before publishing a snapshot, so an old bootstrap cannot replace the current selection or transcript.

Native draft ownership is independent of window existence. Unsent text, attachments, replies, mentions or pending sends veto native close, normal quit and update-install admission. The native window offers explicit Save native drafts (a user-selected private JSON file containing text and attachment references) and confirmed Discard native drafts; discard rejects changed drafts and pending sends. Other-account drafts remain recoverable rather than silently disappearing. The native window retains an Open full client action: onboarding, settings, memory-service sheets and Blobatar editing remain in the working Solid client. Installation also refuses an open native window before evaluating web-page draft guards. This development surface is not the default client or platform-parity acceptance.

Update workers request native ownership admission through `postMain` and wait for its result; they never traverse the main-thread store's draft maps. The final main-thread quit path rechecks ownership before installation approval. The ordered snapshot runs between account transitions, native edits and send completions.

The opt-in native window offers Diagnostics through `native_diagnostics.go`. Generate requests only `diagnostics.report` through the existing admitted account/socket-bound CLI transport; callbacks return on the ordered main queue. The schema-1 allowlist validates required fields, closed enums, release strings and host-only relay disclosure, and discards unknown fields before selectable review or explicit Copy/Export. Request, schema and share failures use fixed messages without raw errors or snapshot fallback. Copy writes only the reviewed JSON to the system clipboard. Export uses an explicit Save dialog and private file mode; pending dialog/file writes veto close, quit and updater admission even after account teardown dismisses the report. Teardown revokes request callbacks and prevents a stale Save-dialog result from starting a write. A write already admitted may finish with the sanitized report the user selected. The core API is not supplied by this native increment; an unavailable method fails closed. Relay public-health checks may occur inside the core report; no provider probe or automatic upload is added.


- **Title bar**: each pane of the main window has a header in its own color: the sidebar's holds the sidebar and Create buttons where the Mac app's titlebar accessory has them, the content's the title and subtitle, back and forward, the Device picker, and running tasks, and the inspector's its toggle. The headers are the title bar: the main window hides its own (`TitleBarHidden`), keeps the window controls over the headers, and the headers are marked `--app-region: drag`. On macOS the traffic lights sit in the sidebar's header (`TrafficLightPosition` at 19, 19, where the Mac app's toolbar puts them). On Windows and Linux MyGo puts the controls in a top corner, 52 pixels tall like the headers (`TitleBarHeight`): on Windows minimize, maximize, and close at the right, drawn as Windows 11 draws them, on Windows 10 too, and on Linux GTK's own title buttons wherever the desktop's button layout puts them, or none. The rightmost header and the sidebar and Create buttons keep clear of them with MyGo's `--mygo-titlebar-inset-right` and `--mygo-titlebar-inset-left`. Onboarding hides its title bar too: its page fills the window under the window controls, the close button alone on Windows since the window can neither minimize nor maximize, and its background drags the window. The small settings window keeps the system's title bar. On Windows and Linux every window's menu bar stays out of sight until Alt or F10 takes the keyboard to it (MyGo's `AutoHideMenuBar`), and its shortcuts work all along; the main window has no room for a bar on Windows, so there Alt and F10 open its menus from the window's top-left corner.
  The taskbar and Alt+Tab title names the current chat or settings pane followed by ` - <app name>`; onboarding and the empty main window show the app name alone.
- **Commands** (`src/ui/commands.tsx`): one table gives the menu bar (File, Edit, View, Chat, Window, Debug, Help, with Settings, Quit, About, and Check for Updates in File and Help), the command palette's titles and enabled states, and the shortcuts in a browser tab, which has no menu bar. Ctrl stands where the macOS app has ⌘; Ctrl+1 to Ctrl+9 are the page's own, since the Windows menu bar keeps no hidden items. While a sheet is up only the app's own commands (Quit, About, Help, Check for Updates) run, as a sheet takes a Mac window's commands.
  Every sheet and alert is a modal `role="dialog"` named by `SheetHost`: the frame takes its own visible title through `aria-labelledby`, or, for a sheet with no `.sheet-title` such as the marketplace, the `aria-label` the sheet declares. A sheet with neither stays unnamed rather than carrying a generic label.
  Under the OS Reduce Motion setting the presence dot, the spinner, the working row's shimmer and the sheet and popover entrances hold still instead of pulsing, spinning, sweeping, fading or sliding; the elements stay and keep their state.
  The Solid command palette uses shared `chats.search` content matches for Chats, Messages and Files, while actions/settings keep fuzzy matching. File rows open the existing owning chat; no file bytes are indexed. Store changes invalidate and refresh an unchanged query. The input names its listbox and active option; arrows select, Return opens and Escape dismisses. An incomplete-history notice identifies local downloaded-history coverage. Task results await the durable task API.
- **Updates** (`updater.go`): the app owns MyGo archive checks and guarded install-on-quit. Every candidate is a stable `beans-v<root version>` release from `bloodf/beans` with signed readiness, a validated archive hash and compatible selected relay. Automatic checks run every 15 minutes when enabled; saved preferences and skipped versions remain in `updater.json`. Users choose Install on Quit, Later or Skip; the app never forces an unattended relaunch. Installation requires the app-owned drain-capable CLI and its private update-control token. Before spawn the launcher supplies only the eventual token path; the current app-owned child's matching READY precedes existing-directory/format admission and exclusive token creation. It creates neither directory nor marker, and preserves existing token bytes and permissions. Explicit operator settings, including an empty disable, remain inherited, but app-owned installation does not read operator token files. Token failure leaves the admitted CLI running with installation unavailable. Quit checks retain drafts and reject running work, pin a separate local websocket to the child PID/launcher generation/selected port, and take a 30-minute Runner admission lease before approval. The page becomes inert during the guard; cancellation restores it and releases the same Runner's lease. Relay selection and lease readiness are checked again before quit. The quit callback waits for the idle child to exit before swapping resources, while retaining the instance lock; Windows stops the approved idle child without waiting for the app's own exit. Native update dialogs use the page's live `L()` bridge. Development and package-managed non-writable installs omit update controls. [Desktop releases](../releasing-desktop.md) describes prerequisites and platform constraints.
- **Device versions**: Device details shows the reported CLI/core version. Beans leaves standalone CLI self-update status absent and rejects its requests; this does not change the app-owned signed updater.

Windows update-control admission queries the opened directory, marker and token handles for owner/DACL evidence. The owner belongs to the current account or LocalSystem; process group membership, including Administrators, is not a privacy grant. Effective foreign token data-read/write grants and directory/marker replacement, write or security-control grants are refused, including inherited grants. Missing DACLs, unsupported ACE forms and security-query failures fail closed. Existing objects are never repaired or repermissioned. Only an exclusively created token receives a protected current-user DACL, which is checked before its secret is written.

- **Development and builds**: `bun run desktop` builds the CLI and runs `mygo dev` (Beans Dev, `app.beans.dev`, with `~/.beans-dev-v2` and port 4875), which reloads the page on a frontend change and rebuilds the app on a Go change; `cd desktop && bun run dev:web` serves the page alone for a browser, where `?mock=1` runs the demo, `?port=4875` selects the matching Dev CLI, and `?platform=windows` or `linux` previews that system's shortcuts and words (Ctrl, Enter). The browser host loads and validates saved/query ports before any WebSocket construction, including early transport initialization and reconnect; invalid values stay offline without rewriting preferences. `bun run desktop:build [platforms]` builds the CLI for each platform into `desktop/resources/<goos>-<goarch>/bin` (static musl builds for Linux, with cargo-zigbuild, as the CLI releases are) and runs `mygo build -platform`; MyGo needs no cgo, so every platform builds from any computer, and a Mac builds Windows and Linux on x86-64 by default.

The Go client's websocket to `127.0.0.1:<CLI port>/ws` sends no `Origin`. A browser tab using `dev:web` connects to that same local socket directly, so its CLI must explicitly allow the Vite page's origin: `BEANS_ALLOWED_ORIGINS=http://localhost:5178,http://127.0.0.1:5178`. `bun run desktop` passes that list to the development app's CLI. When starting `beans serve` by hand for a browser tab, set the same variable on that process; a packaged app leaves the browser allowlist unset. The CLI checks exact `Host` and `Origin` before upgrade.

Stable/Dev defaults use `.beans-v2` / `4874` and `.beans-dev-v2` / `4875`. Native preferences are `preferences-v2.json`; browser and disconnected website preview use separate `beans-v2` keys, without old preference reads or saved-port migration. The updater’s independent selected-relay health GET sends `Beans-Protocol: 5` and `Beans-Format: beans-v2` and requires fresh format, sufficient release protocol, supported effective account/roster floors >=5 and `memory_config_version: 1`. Missing, malformed, duplicated or unsupported capability evidence fails closed. Drain/admission/install sequencing and provider/memory/avatar mechanisms remain unchanged.
