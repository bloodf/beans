# Marketplace

The marketplace (`crates/cli/src/marketplace.rs`), after Grok Bot's, offers plugins and bots: a JSON index of plugin manifests (`plugins`, the [plugins](plugins.md#plugins) a Runner installs) and bot templates (`bots`). An entry with `featured` is listed under Featured Plugins or Featured Bots, in index order, and `category` names its section, one of Grok Bot's filter categories (`credentials`, `productivity`, `communication`, `design`, `code`, `data`, `sales`, `finance`, `research`, `support`). Each remote plugin in the index is the service's own server, and it needs no account, signs in through dynamic client registration with the Runner's loopback redirect (GitHub's device flow aside), or takes a personal API key the user copies from the service (Zhihu, Metaso), so a plugin never asks the user to register an app first. `marketplace { query? }` answers with the plugins, each with the Runners that have it, and the bots, each routine with its schedule in words (`schedule_text`); a query keeps the entries that have every word.

## The index

The bundled index is `crates/cli/marketplace/index.json`: version 1, the UTC time it was `updated`, and the `plugins` and `bots` in order. The configured Beans relay serves `/marketplace/v1.json`; every build retains the bundled index for offline use. A content change must advance `updated` (`bun run check:catalog` and the Catalog pull-request workflow).

**Updating the index**: startup, app bootstrap and marketplace use check at most hourly; `marketplace.reload` forces a check, and a search or install miss may check every five minutes. Requests send a source-bound ETag and no account credentials; failures keep the current index. A validated cache in `marketplace.json` belongs only to its selected source. Changing relays resets to the bundled index before applying that relay's cache. A newer relay index replaces its predecessor; an explicit custom URL overlays entries by id on bundled entries. `LORCA_MARKETPLACE_URL` or `marketplace_url` selects an override, and `LORCA_MARKETPLACE_FETCH=0` disables network checks. Browser stays pinned to its bundled manifest. Model and marketplace fetches share `crates/cli/src/served.rs` ([Providers](providers.md)).

Installed plugins may follow text-only metadata updates. Execution, setup, skills and permission changes require explicit reinstall; existing secrets cannot silently move to a new command or origin. See [installed plugins](plugins.md#plugins).

**Reading an index**: unknown fields are ignored and unreadable, unsupported or duplicate entries are skipped. Version and UTC `updated` validation reject an incompatible index without discarding the current one. The feed is unsigned and can propose executable manifests, so treat the chosen source as trusted for new installations; it cannot silently replace an existing plugin's execution configuration.

## Bots from the marketplace

A bot template is a bot's starting point: `id`, `name`, `summary` (its line in the marketplace), `description` (the new bot's description, so its instructions), `symbol_name` and `accent`, `category`, `featured`, `author`, `plugins` (the marketplace plugins it works with), `routines` (`name`, `schedule`, `prompt`), and `memory` (facts it starts with). `bots.create { template_id, greeting }` makes a bot from one, as Grok Bot's template import does: the template's profile, its routines added paused, and the app's `greeting` ("Hi Researcher, introduce yourself.", in the user's language) as the user's first message in its DM. The turn that answers carries the setup (`Job.setup`: a `TemplateSetup` of the plugins, the routines' names, and the facts), and the Runner puts a cue after the greeting (`turns::setup_cue`): save the facts with `memory_update`, ask once whether to turn the routines on and resume them only on a yes, call `install_plugin` for each plugin the Runner lacks (the user allows or denies each on its card), and greet the user. The cue exists only in that turn's context; the chat keeps the greeting and the reply.

## In the apps

The macOS marketplace (`macos/Sources/Lorca/Marketplace/`) is a sheet, as Grok Bot's is an overlay, of up to 800 by 700: the marketplace icon at the foot of the chats' sidebar opens it, as do File › Marketplace… (⌘⇧M, so the command palette has it too), Add from Plugins… in a DM inspector's Plugins section (on that bot's Runner), and the same row in Settings › Plugins (on the picked Device). Its top bar has Back, the Runner that plugins install on and bots are added to (a pop-up when there are two or more), and Close, which Escape presses from any page. The home page has the title with "N installed" (the Runner's plugins, on a page of their own), the search over plugins and bots, and then Featured Plugins, Featured Bots, and a section per category (its plugins, then its bots, leading with what the featured sections do not show and keeping half the rows for bots when it has both), each a two-column grid of up to four rows with View all (a featured section's lists every plugin or every bot, the featured ones first); a query puts the results in their place, and a category's View all or the results offer All, Plugins, and Bots when both kinds are there. A plugin's row offers Add, then shows Added, Connect, or Set Up (the last two open the plugin's own sheet); its page has the description, its state on the Runner with Manage…, its servers, skills, and setup variables, and its developer, category, and website. A bot's row and page offer Add; its page shows Instructions, Memories, Routines, and Plugins beside a list of the four, as Grok Bot's does, and adding the bot closes the sheet on its chat. The plugins' marks, rows, and sheets elsewhere in the apps are in [Codemode and Plugins](plugins.md#plugins).
