# MCP servers

A Runner keeps custom MCP servers in private `mcp.json` under its CLI data directory. The file uses `{ "mcpServers": { "name": { "command": "…", "args": [] } } }`; remote entries use `type: "http"`, `url`, and optional `headers`. Entries may also set `env`, `cwd`, `description`, `disabled`, `timeout`, `oauth`, `toolExposure`, and `exposure`. Each valid enabled entry becomes a Runner plugin (`source: mcp.json`, server `mcp`), visible to bots through codemode and subject to their plugin capabilities and Auto-review. A disabled or invalid entry does not run.

## File and lifecycle

`plugins::mcp_json` reads ordered JSON at startup and on `mcp.reload`. Its parser accepts common Claude Desktop, Cursor, VS Code, Windsurf, OpenCode, Zed, and Gemini spellings; writes canonical fields while preserving other fields and entry order. Invalid JSON leaves previously loaded servers in place and blocks writes until repaired. A saved, newly enabled, or changed server drops its old connection and tool catalog; ready servers connect in the background to populate `catalog.json`. Changing only tool visibility leaves the connection intact. Removing a server removes its sign-in, cached tools, and Auto-review rules. Renaming moves these under the new plugin id.

An MCP command starts on the Runner in the configured `cwd`, or its plugin folder. `${VAR}` reads the Runner's login environment and `${VAR:-default}` supplies an unset value; `~/` expands to the home folder for commands, arguments, and working directories. An unset header or environment value with no default is omitted. `timeout` is seconds, or milliseconds for values at least 1000; omitted calls allow ten minutes.

`toolExposure` maps exact tool names or trailing-`*` patterns to `hidden` or visible; exact names win over patterns. `exposure: hidden` hides unnamed tools. Codemode excludes hidden tools from the listing and checks current visibility again before execution. Every tool that is not marked read-only by the live server or manifest goes through Auto-review. The Runner's account Pause and bot capabilities are checked before and after connection.

A server advertising resources supplies `list_mcp_resources`, `list_mcp_resource_templates`, and `read_mcp_resource` as read-only script tools. Resource lists page with the server's cursor; text is returned to the script, images are decoded and scaled before reaching the model, and other binary bytes go to a private temporary file whose path the result names. Tool-list refreshes honor `list_changed` and stop after 100 pages or a repeated/empty cursor. Requests obey their per-server timeout and Stop sends MCP cancellation; transient HTTP handshakes retry briefly. Child stdio server process groups end with their connection, and startup errors include bounded stderr. Completed tool and resource responses exceeding 8 MiB are refused before they are copied into the script VM; this is a response-processing bound, not a limit on transport frames already received.

## Authentication and privacy

A remote server with an `Authorization` header uses that header; otherwise OAuth is optional until a 401 asks for sign-in. Sign-in tokens and challenge state stay in the Runner's private plugin secrets file, scoped to the remote origin; a changed origin cannot reuse them. `oauth` may specify client id and secret, scopes, registration name, fixed loopback callback port/URL, and authorization metadata URL. A fixed callback opens on the Runner. The regular plugin sign-in flow opens on the requesting Device when possible. Signing out forgets local tokens, without revoking server-side tokens.

The relay sees only plugin status in the Runner's encrypted machine blob, not `mcp.json`, its environment, headers, or tokens. Remote settings travel only in sealed Runner requests. Connection status names a URL by origin, not its path or query, which may contain credentials. `mcp.get` deliberately returns full config to paired Devices authorized to manage that Runner; apps must treat it as secret-bearing.

## Management

`lorca mcp list|get|add|add-json|remove|enable|disable|hide|show|sign-in|sign-out|reload|import` talks to a running local `lorca serve` or acts on the local Runner. The app/API uses `mcp.list`, `mcp.get`, `mcp.save {name,previous_name?,config}`, `mcp.remove`, `mcp.set_enabled`, `mcp.hide_tool`, `mcp.reconnect`, `mcp.sign_in`, `mcp.sign_out`, `mcp.reload`, and local `mcp.parse {text}`. Except parse, these accept `runner_id` and travel as sealed requests to another Runner. List returns `{path,error,servers}`; get returns `{path,server}`, including cached tools. Broken individual entries carry `problem`, and their config can be any JSON value. Apps use `plugins.connect` for a sign-in browser on the requesting Device.
