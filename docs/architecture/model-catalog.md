# Model catalog and cost

**The model catalog** (`crates/models`, `beans-models`, a snapshot of models.dev that `beans-agent` re-exports as `beans_agent::models`) knows each offered model's context window, output cap, image support, thinking levels, and rates. It is its own crate so the phone's core, built without the agent, has it too. The snapshot carries its `models`, and every app's Model and Thinking pickers come from them, so a new model is added in the catalog alone. The Thinking picker offers Default and only the levels the bot's model takes, the default model's when the bot has none, and every level the provider has for a model the catalog lacks; a model without levels shows no Thinking picker, and picking another model returns a level the new one does not take to Default. Every assistant message carries `usage.cost`: its dollar fields are the known subtotal, and `known` is true only when all contributing calls have known rates. Missing rates produce unknown cost; explicit zero rates produce known zero. ChatGPT and Grok sign-ins are not billed per token; their known cost is what the work would cost at API rates, not a provider bill. `usage.input` is the input read fresh and `usage.cache_read` the input served from the provider's prompt cache: Messages reports the two apart, and the adapters for Chat Completions and Responses, which count cached tokens inside their input total, take them out of `input`. The Runner adds each turn to the chat's `usage` (`context_tokens` and `context_window` of the last turn, totals of tokens, cost, and turns), kept in the local database and never synced. Chat `cost_usd` retains the known subtotal and `cost_known` records completeness; missing historical completeness is unknown. Side calls preserve this same monetary state without changing context or turn counts. The app gets usage in the snapshot, in `roster.changed`, and as `chat.usage` events. The desktop DM inspectors show "Context 128k of 1M · 13%" and known spend such as "Spent $0.42 · 18 turns"; unpriced work shows "Unknown cost", and mixed work labels the known subtotal with "total unknown".
The CLI keeps the version-1 bundled `crates/models/catalog.json` available offline and checks the selected Beans relay's public `/models/v1.json` for a newer validated catalog. Checks at startup and bootstrap are at most hourly; `models.reload` forces one, and a turn on an unknown built-in model checks at most every five minutes. A 1 MiB response cap, version and UTC time validation, supported model wires and thinking levels, and required review-model mappings protect the runtime catalog. A cached index and its ETag belong only to the relay URL that supplied them; changing relays resets to the bundled snapshot before using that relay's own cache. `BEANS_MODELS_URL` explicitly selects another source and `BEANS_MODELS_FETCH=0` disables network checks. No provider keys or account bearer are sent with public feed requests. Provider adapters hold the model metadata of their turn in an owned snapshot, so a refresh cannot change a running turn.
