# Phone interface

Native screens, transcript presentation and adaptive navigation for the [phone app](phone-app.md).

The UI is native: a native stack with large titles, search, and toolbar items; a composer after Grok Bot's phone app, a liquid-glass `+` button and glass pill (`expo-glass-effect`, a filled pill where glass is unavailable) floating over the transcript with the Dictate or Send disc inside the pill's right edge, riding the keyboard as a `KeyboardStickyView` while the transcript's `KeyboardChatScrollView` lifts the last messages with the keys by growing its bottom inset, so the list is never resized; form sheets on iOS and full-screen Material modal screens on Android for chat info, new bot, new group, and settings.

The iOS attachment disc in `src/ui/Composer.tsx` claims the start responder around its hosted SwiftUI menu. Its touch does not reach the enclosing pill's focus action, so opening attachment sources does not focus the field or expand the idle pill. Taps elsewhere on the pill still focus the same multiline input; menu touches leave the draft intact. The hosted menu ignores the keyboard safe area because the sticky composer already follows the keyboard. Android retains its attachment button and Material bottom sheet.

The composer retains text, attachments, mention picks and reply in a process-memory draft keyed by the current account identity, relay URL and chat. Typed and dictation Send share one pending submission; navigation and replacement mounts retain that ownership. A `chats.send` acknowledgement validates the complete user-message shape, Rust-trimmed submitted text, ordered attachment metadata and selected reply ID before store mutation; only that success clears the unchanged submitted revision. Refusal or an ambiguous transport outcome retains the draft without automatic retry or a claim that nothing happened. Account, Device and relay transitions revoke pending clear and microphone-permission authority, including changes away and back; changing the presented draft cancels its permission attempt, retains heard dictation text, aborts recording and resets recording controls. Permission and recording-start errors release ownership. Late replies cannot update another source's store or a replacement screen's anchor. Manual clearing releases empty detached drafts. The current store's explicit chat removal discards that source's draft, and account reset/forget discards all drafts; roster omission alone does not discard content. Drafts and picked file paths do not survive process death or cache eviction. This composer retention does not introduce an updater draft-veto integration.

A Device's screen under Settings (`app/settings/device/[id].tsx`) shows its reported CLI/core version without self-update controls or an unchecked up-to-date claim; see [CLI service and updates](service-updates.md#service-management). Provider credential screens use API-key fields and an in-app browser for subscription OAuth, the same browser that opens a computer's plugin sign-in from its card. Custom providers follow the built-in ones; OpenAI Compatible and Anthropic Compatible open the explicit protocol form (`app/settings/custom-provider.tsx`: name, API menu, base URL with the URL the CLI will call and, for a server on localhost, a note to name it as the Runners reach it, optional key, a Models row, and a Default Model menu). Models slides in the server's listed models with a native search bar offering Add "…" for an unlisted id (`app/settings/custom-models.tsx`); the forms share rows through `src/ui/modelDraft.ts`.

Settings › This phone › Diagnostics generates a report only after an explicit tap, using the local native core’s `diagnostics.report` method. The screen validates schema 1 and rebuilds a recursive allowlist before displaying selectable JSON; Copy Report and Share Report use those exact reviewed bytes. Disclosure names the selected relay host/port, including private hosts, configured-only providers, cached plugin setup, Runner presence rather than work readiness, and the busy-port limitation. The core may check public relay health; the screen never uploads automatically or probes providers. Unsupported schemas, invalid reports and request/copy/share failures display fixed localized messages, with no raw error or snapshot/status fallback. Existing observable ready/paired identity, Device, relay URL, connection and update-required fields fence account authority; their transitions, route blur and backgrounding discard the report and invalidate pending completions. An explicit OS copy/share already admitted under captured authority is not rolled back by later teardown. English and Simplified Chinese use the existing phone translation table.

Each reviewed diagnostics report retains its validated request generation. Copy/Share admission compares that stored generation with the current generation, and completion uses the same stored token, so an account or lifecycle change away and back cannot reauthorize a stale rendered report before React clears it.

Link previews and context menus on iOS chat rows and Material long-press menus on Android; SF Symbols on iOS and Material Symbols on Android; UIKit semantic colors and Material 3 dynamic colors; haptics. Android toolbar actions and popup menus are Jetpack Compose views from `@expo/ui`: the chat list has Settings on the leading side and Search plus the New menu on the trailing side, with no title, while the composer's attachment sources open in a Material bottom sheet. Conversation headers overlay the transcript on both platforms; UIKit supplies its navigation material, while Android lays a nearly opaque light or dark veil through the status-bar and controls and fades it into the transcript, leaving scrolled messages faintly visible like Gemini.

Rendering colors come from `src/ui/theme.ts` through the shared `usePalette(): Palette` hook. Light and dark appearances each retain one palette object, preserving UIKit semantic colors and Material 3 dynamic roles without reconstructing them on unchanged renders. Android consumers share one AppState listener while mounted; a transition into active clears both appearance slots and notifies every consumer. The first subscription after a period without consumers also clears Android slots. Native color failures do not populate a cache slot. iOS keeps its semantic palettes across foreground transitions; appearance changes select the matching palette, including its bubble and code-fade colors. Markdown's native adapter (`modules/beans-core/MarkdownView.tsx`) retains up to 128 successful measurements in least-recently-used order, keyed by exact text, width, body/code font sizes and current font scale; text over 16,384 UTF-16 code units bypasses retention. Failed measurements propagate without caching, and an absent optional native measurement returns undefined. `src/ui/Markdown.tsx` reads reactive window font scale: iOS applies it once to identical measurement and drawing sizes, while Android passes unscaled font sizes to its SP-based renderer. Width remains in points.

The transcript follows the macOS app: bubbles with the bot's name above and its avatar beside the bubble's bottom edge in a group, neither in a DM; "Today 4:13 AM" separators after fifteen minutes; the "is working" row ("Working…" in a DM, "Chef is working…" in a group, or what the one working bot is doing, in the Mac's words and by its rules, such as "Thinking…" or "Running command: Install dependencies…" (`workingActivity` in `src/ui/format.ts`), its words shimmering inside `ShimmerView`, a native container in `beans-core` that masks its children with the Mac's sweeping gradient) and the breathing green dot on avatars; "Message from ◉ X" and "Messaged ◉ X" markers; tool calls never shown, except a `bash` call's command card while the command needs the user, after the Mac's (`showsCard` in `src/core/model.ts`): the command's first line in a code block that opens the whole command in a sheet on tap; while Auto-review asks, its question with the answers; once the bot handed the running command over, Stop on the title's line and its last lines in a code block that scrolls past six lines, fading at an edge with more past it (Android's `fadingEdgeLength`, a gradient in the block's color on iOS); at a question, Answer, which opens `@expo/ui`'s bottom sheet sized to its content (SwiftUI's on iOS, Material's on Android; `src/ui/AnswerSheet.tsx`) holding only a field, with the command's question as its placeholder, that takes the text as typed, without capitalization or correction, and hides it unless the question is a yes or no, and Send; the sheet closes when the command ends; Running tasks (see [Terminal sessions](terminal-sessions.md)) as a terminal button beside the chat's ⋯ (a native bar button on iOS, the Android header's own button), which opens them as rows in a sheet with its own stack (`app/tasks/`), each sliding in its command's details: the bot and how the command stands, Run in Background while the bot's call waits on it, Stop Command, the whole command, and its last lines; sidebar-style previews and stamps, and in the chat list, while a chat has a turn in flight, three dots lighting up in turn and "Working…" in place of its preview.

Reply gestures (`src/ui/transcript.tsx`) begin on the message bubble, not its row’s empty space, avatar, author, quote or Send now control. A rightward drag moves the whole row and reveals a reply arrow; releasing a successful drag at or beyond 56 pt selects that message for the composer’s reply without sending or replacing its text draft. Touches starting within the screen’s leftmost 28 pt fail reply recognition for back navigation; before activation, leftward movement beyond 10 pt or vertical movement beyond 10 pt fails it for navigation or transcript scrolling. Cancellation, including a native child scroller taking ownership, does not select a reply, and the row returns to its resting position. Bubble and Markdown widths continue to use the current pane and font-scale layout. Installed iOS and Android navigation, horizontal code scrolling and large-font gesture-arena proof remain pending under issue #280.

Foreground chat reads and the chat list’s Mark as Read action dispatch `chats.mark_read` through the bundled native request bridge. For a chat with unread messages, the local API commits the cleared read state and encrypted `ClearUnread` outbox item in one SQLite transaction before publishing the in-memory clear and roster event. Account-key, encryption and storage failures return an API error without clearing that state or admitting the outgoing operation; retry after a successful clear admits no duplicate operation. An already-read or absent chat remains a successful no-op. The phone store clears the unread badge only after a reply without native rejection or decoded API error. Account, device, relay-source and foreground transitions revoke in-flight completions, including transitions away and back. A completion cannot clear a newer roster or message’s unread state. Incoming paired-Device read marks decrypt before SQLite admission and commit the unread clear, incoming receipt and forward-pull cursor together before publishing the clear. Storage rejection leaves that read mark retryable and stops the page before advancing past it, including bulk pages; earlier accepted operations remain accepted. First-sync chat pages commit read marks without advancing the forward cursor, and older transcript paging ignores historical read marks. Production-bundle read/restart and paired-Device synchronization proof remain pending under issue #279.

A window at least 700 pt wide (a tablet, or a tablet window with room to spare) shows two panes (`app/(main)/_layout.tsx`, `src/ui/layout.tsx`): the chat list as a sidebar (320 pt, 375 pt from 1100 pt) and the open chat beside it; a narrower one stacks the chat over the list. The route group `(main)` holds the list and the chat in a stack of their own inside the root stack, so sheets and the pairing screen cover both panes. The sidebar (`src/ui/Sidebar.tsx`) is the same `ChatsScreen` in a native stack of its own, one screen deep, in an independent navigation tree, so it keeps the native bar and toolbar buttons; the pane's stack starts at an empty "Select a chat" screen, a chat picked in the sidebar replaces the one open, its row stays lit, and the chat's bar has no back button. Sidebar rows open their menu on a long press on both platforms, with no Link preview. On iOS the sidebar sits in a `CompactWidthView` (`modules/beans-core`), a container that overrides the horizontal size class to compact as a split view's sidebar column does. On both platforms the sidebar's search field is a capsule at the foot of the list (`src/ui/SidebarSearch.tsx`; glass on iOS, filled on Android), level with the composer and riding the keyboard: UIKit moves a search bar into the bottom toolbar only on an iPhone, and on Android the search action is an item of the activity's one action bar, which react-native-screens hands to whichever stack updated its header last, so a sidebar's item would vanish once the pane opens a chat. The transcript sits in a `SoftScrollEdgeView`, which gives its scroll view the soft top edge a phone has where an iPad would rule a line under the bar. Bubbles and Markdown measure against the pane's width (`usePaneWidth`) and stop growing at 620 pt.

The chat list and tablet sidebar use shared `chats.search` results rather than client-local title predicates for content queries. Chat, message and attachment-filename rows open the existing chat; file rows identify Files, and accessible button labels include result type, chat title and snippet. Roster/message changes refresh an unchanged query. Search uses canonical local rows without reading attachment bytes or sending the query to the relay, and displays a downloaded-history limitation when older pages remain. Durable task results await the task API.
