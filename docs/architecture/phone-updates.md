# Phone releases and updates

iOS builds go to TestFlight, which updates them. Android GitHub APKs ship on the same stable `beans-vX.Y.Z` releases as the rest of Beans (`Beans-X.Y.Z.apk`), made by `scripts/android-release.ts` and the all-scope release path ([Releases](releases.md)). The version is the root `package.json` version that `app.config.ts` reads; EAS remote versions own store Android versionCode and iOS buildNumber. Store Play AAB and TestFlight IPA updates stay with those stores.

The Android production app (`ai.amoena.beans`) can self-update from those GitHub APKs (`mobile/src/core/updates.ts`) only when `beans-core` exports both `installUpdate` and `onInstallStatus` at runtime. Without that native installer, `updatesSupported` is false: the daily check never runs, nothing is offered, and the progress dialog never opens. Beans Dev (`ai.amoena.beans.dev`) never updates. iOS is unchanged (TestFlight only).

When the native functions are present, once a day at launch or back in the foreground the app reads the `beans-v` tags through the GitHub API, takes the newest published release newer than itself that has a digest-backed `Beans-{version}.apk`, and offers it in an alert with the release's notes (Install Update, Remind Me Later, Skip This Version). Prefs hold the daily-check switch and skip choice.

Install Update opens a Material dialog (`src/ui/UpdateProgress.tsx`) with the download's percent and a progress bar, indeterminate once the installer has the APK, until the app restarts; Hide puts it away while the download goes on, and a failed download or install is said in an alert. The native Updater (when linked in `beans-core`) downloads the APK, checks it against the size and SHA-256 GitHub lists for the asset and that it is this app and newer, and commits it to a `PackageInstaller` session, which installs only an APK signed with the installed app's key and then stops the app. It asks for no confirmation from Android 12 (`UPDATE_PACKAGES_WITHOUT_USER_ACTION`) once the user has let Beans install apps; otherwise the installer's confirmation shows, from the foreground. The native Android updater itself is tracked separately (TODO) and is not part of this JS progress-dialog slice.
