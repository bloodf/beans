# Approval and policy history

## Approval and policy history

What each decision writes, where, how long it stays, what a client shows. "Existing" = durable record, "partial" = current state only, "missing" = no durable decision history. Client columns describe the Solid desktop interface in `desktop/src`; they do not establish parity with the native Go, macOS or phone interfaces.

| Decision | What is written and where | Retention | What a client shows | Class |
| --- | --- | --- | --- | --- |
| Permission card allow | Card `decision` becomes `allowed` (`plugins/mcp.rs` `ask_with_rule`); shell cards keep `run.decision` (`local_review.rs` `ask_on_card`). `Body::Permission` in `messages` (`local_store.rs` `upsert`); synced as encrypted `chat` blob, first and last versions (`app.rs` `push_chat_op`) | Until chat delete: bot DM rows go (`local_store.rs` `save_state_deleting_chats`); relay drops the group's blobs (`crates/relay/src/db.rs` `Store::delete_group`) | Answered card in the transcript (`desktop/src/ui/chat/cards.tsx`); no decision list | Existing for the card, missing for a list |
| Permission card deny | Same card with `decision` `denied`; call blocked, bot told not to retry (`plugins/mcp.rs` `review_call`) | As above | Same card, reading as the denial | Existing for the card, missing for a list |
| Always allow | Card `decision` becomes `always`; Auto-review rule joins the roster: `AutoReviewRule { id, text, behavior, tool? }` (`model.rs`; `app.rs` `add_auto_review_rule`), in the encrypted roster and `metadata.auto_review_json` (`local_store.rs`) | Current rules only: `auto_review.set` replaces the list (`api.rs`); same-tool or same-words rule replaced in place. No add/remove history | Switch and rule list in Auto-review settings (`desktop/src/ui/settings/panes.tsx`) | Partial: rule kept, history not |
| Auto-review verdict | Transient `Outcome` (`plugins/review.rs` `decide`); raw reply to the debug log | Nothing durable. An `ask` reason rides on the card; an `allow` verdict is written nowhere | Reason on the card; no verdict log | Missing |
| Pause and Resume | Account `paused` flag with policy version, plus encrypted `policy` action (`model.rs` `PolicyBlob`; `app.rs` `set_paused`). Flag in roster and `metadata.paused` (`local_store.rs`); relay keeps the envelope, which no blob or group delete removes (`crates/relay/src/db.rs` `Store::delete_blob`) | Locally latest state and version only; events not kept. Each event's envelope stays on the relay as ciphertext until account data is deleted; authenticated replay is available, without a client history view | Pause switch on every Device (`desktop/src/model/store.ts`) | Partial: state kept, events not |
| Capability edit | Bot's new `capabilities` in the roster, plus encrypted `policy` action with them and a version (`app.rs` `update_bot`). Roster holds values; `metadata.policy_json` holds `capability_versions` and `policy_capabilities` (`local_store.rs`); relay keeps it too | Current capabilities and last-edit version; earlier values not kept. Envelope retention as for Pause | Capability switches in the inspector (`desktop/src/ui/inspector.tsx`) | Partial: current value kept, edits not |
| Bot deletion | Tombstone: bot id maps to its deletion's policy version (`model.rs` `RosterBlob`; `app.rs` `delete_bot`), reconciled in `sync.rs` `apply_policy`, so a stale roster cannot restore it. In `metadata.policy_json`; a `policy` envelope carries `removed: true` | No expiry in the source. Bot DM and transcript rows go with it (`local_store.rs` `save_state_deleting_chats`), so a card there goes too | Bot leaves the sidebar; no client shows it was deleted, or when | Partial: fact durable, event not |

A pending decision's waiter is transient: it lives in an in-memory map on the Runner (`App::pending_permissions`, `app.rs`), so a late answer reaches no waiter (`plugins/mcp.rs` `answer`). Unanswered for ten minutes → `expired` (`plugins/mcp.rs` `PERMISSION_TIMEOUT`); a new user message, or Stop on an unanswered call → `dismissed` on the stored card—both kept like an answer. Startup and later sync dismiss this Runner's orphaned `propose` cards (`app.rs` `close_orphan_proposals`). Other permission cards retain their stored decision across a restart, even though the waiter is gone. Cross-Device: answered cards sync as encrypted `chat` blobs every paired Device pulls; an answer given elsewhere is sealed to the bot's Runner (`api.rs` `chats.permission`).

The relay also exposes bounded authenticated replay of retained ordinary and managed policy envelopes, with immutable managed receipts; see [Managed policy receipts and replay](managed-policy-replay.md). This ciphertext history is separate from a user-visible audit log. The CLI inspects replay in memory without persisting or presenting a decision timeline; protocol-6 managed authority remains inactive.
