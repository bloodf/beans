# Remote requests

## Request authentication

All sealed remote request verbs wrap their body in `{ payload, signature }`. The Ed25519 signature binds a domain, request ID, verb, requester signing public key, target Runner, creation time and payload. The three guided provider verbs retain their existing `beans-provider-request-v1` domain and wire format; other verbs use `beans-request-v1`. The shared Runner request dispatcher checks current local paired membership and verifies the signature before executing any verb. A relay-listed Device with missing metadata remains eligible; a claimed `requested_by` inside an anonymous sealed box alone is not authenticated authority. Removed requesters, unsigned bodies and forged signatures reject before dispatch. Previously queued unsigned requests are not re-signed or executed; paired clients must upgrade together for remote requests. This request-body cutover does not change protocol 5, the account format or stored account data. Membership is admission-time authority, not a promise to roll back already-started asynchronous effects. Guided provider membership remains checked through the post-discovery credential commit. Guided clients retain a UUID `custom:setup-*` kind for add retries; exact committed replay returns the same kind and stamp without another catalog request.

## Delivery and timeouts

`kind=request` sealed to one Runner (`crates/cli/src/requests.rs`: `{ id, verb, requested_by, body }`), answered with a `kind=response` sealed to the Device that asked (`{ request_id, body, error? }`); each side deletes the blob it consumed, and the asker gives up after 20 s, or 75 s for the start of a plugin sign-in, whose discovery and registration the Runner cuts off at 45 s, or 150 s for `mcp.reconnect`, which answers once a server has connected or failed. The verbs are `memory.read` and `memory.write`, so a bot's memory can be shown and edited from a Device that is not its Runner; `plugins.install` / `plugins.uninstall` / `plugins.variables` / `plugins.connect` / `plugins.sign_out` / `plugins.detail`, so plugins on a Runner are managed from any Device, and `plugins.sign_in.finish` / `plugins.sign_in.cancel`, with which the Device that asked for a sign-in (its `redirect_uri` on `plugins.connect` or `permission.answer`) hands back where its browser landed (see Sign-in in [Codemode and Plugins](plugins.md#plugins)); the `mcp.*` methods but `mcp.parse`, so a Runner's own MCP servers are managed from any Device; `permission.answer`, so a permission card is answered from any Device; `bash.stdin`, `bash.stop`, and `bash.background`, so a command a bot runs is answered, stopped, or sent to the background from any Device; `chats.send_now`, so a message the bot's turn holds is read at once from any Device. A request is refused up front when the Runner is unknown or offline.
