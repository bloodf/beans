# Secrets and full access

`crates/cli/src/secret_shield.rs`, `crates/cli/src/secret_store.rs`, and the review boundary in `crates/cli/src/local_review.rs` and `crates/cli/src/turns.rs`. How a bot works with the user's secrets without a model ever seeing them, where it keeps the ones it sets up, and the switch that lets bots act with no review at all. Shell review and Auto-review themselves are in [Tools](tools.md).

## Secret shield

A model never sees the values of the user's secrets, and cannot send one anywhere without the user. Each secret reaches it as a placeholder, `{{secret:NAME}}`. The Runner keeps the values in memory (`App::secrets`), learned from the environment commands run with (variables with a secret's name, such as `*_TOKEN`, `*_API_KEY`, `*_PASSWORD`, `DATABASE_URL`, and values that are secrets anywhere, such as a URL with a password), the account's provider credentials, plugins' secrets and MCP servers' `env` and `headers`, and any text passing out: `NAME=value`, `NAME: value`, and `"name": "value"` with a secret's name, `Authorization` headers, URL passwords, private keys, and known token formats (`sk-…`, `ghp_…`, `xox…`, `AKIA…`, JWTs). Values shorter than eight characters, paths, and references such as `${API_KEY}` are left alone; a stored secret of four to seven characters is hidden only as a whole word. A value is hidden as it is, JSON-escaped, percent-encoded, and in base64, in one pass over the text that keeps placeholders already there whole and hides values that overlap together, so redacting twice changes nothing. Three places apply it. Every model call goes through `provider_for`, which wraps the provider (`ShieldedProvider`): the system prompt, the user's messages, tool results, and the model's own text are redacted before they are sent, and signed thinking is sent back as it came; turns, Auto-review, compaction, scripts, and schedule reading all use it, and text sent to an embedding API is redacted the same way. `after_tool_call` redacts every result, its `structured` output for codemode scripts, and its details, so the transcript holds placeholders too; the command card the user sees keeps the real output. `before_tool_call` checks what a call carries (`check_call`). `write`, `edit`, and `propose` replace placeholders with the values, so the model reads and edits `.env` files and configuration as usual and the file gets the real value. That needs no question only for a file whose job is to hold secrets (`.env`, `.env.*`, `*.env`, `.dev.vars`, `secrets.*`, key files, `.npmrc`, `*.tfvars`, `local.settings.json`, …) inside the working folder, links followed: a secret written into code, a script, or `package.json` could be sent by running it, and one written outside the working folder, on a network share, or in a synced cloud folder could leave the computer, so those ask the user. Only the text a call writes anew counts, not `edit`'s old text; a placeholder the Runner does not know (it forgets them when it restarts) is refused with a note to read the file again. A shell command that names a secret variable (`$GITHUB_TOKEN`), reads the environment wholesale (`env`, `printenv`, `set`, `/proc/*/environ`, `os.environ`, `process.env`, `getenv(`), holds a placeholder, or names a file known to hold secrets (one the model wrote a placeholder into, or whose contents showed one), `bash_input` that types a placeholder, and a plugin call whose arguments hold a placeholder or a value all skip the fast path, Auto-review, and allow rules, and ask the user on the card or a permission message, naming the secrets, with no Always allow; in a routine they are refused. Once allowed they run with the values in place of the placeholders. Programs still read the environment and files themselves, so builds, tests, dev servers, CLIs, and MCP servers work unchanged, and their output is redacted on the way back. What the shield does not see: a program written to read and send the environment without naming it in the command (that command gets Auto-review as any other), secrets that neither their name nor their format gives away, values under eight characters, and transformed values (encoded, reversed) in output, which only commands that name a secret could produce and those ask first.

## Secret store

Secrets a bot meets while setting something up (the client secret Google shows once for a new OAuth client, a token a dashboard generates, a key in a downloaded file) are kept on the Runner by name with the `secrets` tool, and the bot never sees a value. `save` takes one from the clipboard after the bot presses a page's Copy button (the clipboard is emptied after), from a file (`key` is a dotted JSON path such as `web.client_secret`, or a `.env` variable), or from a placeholder the shield put in a value's place on a page, in a file, or in command output; `generate` makes a random one (hex, base64url, or letters and digits, 16 to 256 characters); `list` names them with where each came from and the uses allowed always, never a value; `write_env` puts named secrets into a `.env` file (existing lines replaced, the file readable by the user alone, and marked as holding secrets); `delete` and replacing a secret with another value ask the user, and are refused in a routine; `revoke` forgets grants. The store is `secrets.sealed` in the Beans home, XChaCha20-Poly1305 under a key derived from this machine's own secret (`keys::secrets_key`), so it opens on this computer alone and is never synced; a store the machine cannot open is never written over. Stored names are their placeholders' names in the shield from then on, across restarts. A bot uses a secret by its placeholder: in `write`, `edit`, or `write_env` with no question, since the value stays on disk; in a shell command (`vercel env add`, `gh secret set`, `fly secrets set`) or a plugin call (a browser typing into a dashboard) after the user allows it on the card. The card offers Always allow as a grant, kept in the store rather than as an Auto-review rule: for a command, that exact command text in that working folder; for a plugin call, that tool with those secrets. A granted use runs without asking, in a routine too, and anything else asks again. A plugin tool's grant covers its secrets only: the call still gets the review it would have had without them. Deleting a secret removes it from its grants (a tool keeps its other secrets) and stops its placeholder resolving, while its value stays hidden. The shield also recognizes Google client secrets (`GOCSPX-…`) and a long random-looking word shown right after a label such as "Client secret" or "API key" on a page. A screenshot cannot be redacted, so once a secret went to a plugin (typed into a browser) or its text showed one, that plugin's images are withheld with a note until its text shows no secret again; the tool and the system prompt also tell bots to copy a secret instead of taking a screenshot of it. Code a bot writes that reads the secrets (the whole environment, a secret variable by name, or a file for secrets by its path) is remembered like a file holding them, so running it asks; an app reading one setting, such as `process.env.PORT`, is not.

## Full access

Full access (`AutoReview::full_access`, set with `auto_review.set { full_access }` and shown in the apps' Auto-review settings, which ask before turning it on) skips all of it: shell commands, typed input, plugin actions, plugin installs, files outside the working folder, uses of secrets, and the secrets tool's own questions run at once with no review and no question, in routines too, and the system prompt tells the bot so. What still holds with it on: a bot's capabilities, Pause and Stop, an unknown placeholder's refusal, and the secret shield's redaction, so a secret's value still never reaches a model. A Device that does not know the setting reads it as off, and an app that does not send it leaves it as it is.

## Not covered

A bot's `xargs wc -l` can be handed a device file's path, since the fast path cannot see what `xargs` reads; `wc` only counts. Full access applies to every bot on every Device: a per-bot switch needs a new capability field, which Devices that do not know it refuse to read.
