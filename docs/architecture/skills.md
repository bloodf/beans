# Skills

## Skill metadata discovery

`beans_agent::harness::skill_discovery::discover_skills` is a read-only source primitive over one caller-selected absolute directory, not an import or runtime activation path. It scans independent `SKILL.md` files without automatic home/host-root discovery, host precedence, directory claiming, ignore-file reads, grants, resource loading or execution. Per call, hard public bounds are 4,096 directory entries (including non-skills and failed opens), 256 candidate files, 64 KiB total file size and frontmatter read budget per file, and directory depth four (root depth zero). Limits and rejected or unreadable paths produce diagnostics; enumeration order can determine which subset fits a limit, while returned metadata paths are sorted. Linux requires kernel `openat2` support: the absolute root is opened relative to `/` with beneath/no-symlink/no-magic-link resolution, including all ancestors; every subsequent directory/file open resolves from that pinned root with the same restrictions plus no mount crossing. Ancestor or child replacement cannot redirect reads outside that root object; the scan is not a coherent snapshot, does not detect in-place edits, and does not establish hard-link provenance. Unsupported platforms, kernels and secure-open operations fail closed with diagnostics, never a canonicalize-then-open fallback. Returned relative paths are labels, not reopen capabilities. Only bounded frontmatter reaches the existing flat scalar parser; buffered reads may prefetch bounded body bytes but no body is parsed, returned or executed. Fields other than name, description, license and compatibility, structured constructs and uninspected sidecars/resources are warned about, not interpreted as host policy. Missing name/description is diagnosed without fallback. Flattened fields are not lossless YAML or raw provenance; body-only constructs are outside this metadata scan. No selected directory is written.

`skills.discovery` takes `{version:1, runner_id, root}` with an explicitly selected current desktop Runner and an absolute directory on it. Existing signed requests route read-only scanning to that Runner; current actor membership, selected Runner binding and local account incarnation are rechecked after waiting. Rust dispatch and the desktop adapter independently decode and rebuild the same version-1 metadata contract: at most 256 skills and 4,096 diagnostics; required relative labels are nonempty and at most 4,096 UTF-8 bytes, with no control characters, backslashes, colons, empty segments or dot traversal; name/license are nullable strings of at most 256 bytes and description at most 2,048 bytes, without controls. Diagnostics carry nullable relative labels and fixed codes. Wrong shapes, missing or unknown fields, invalid enums and oversized values reject the whole response with fixed errors. Local projection excludes body, resource, hook and environment fields and raw scanner errors. An authorized malicious Runner can invent a schema-valid description; decoding cannot prove frontmatter provenance or semantic absence of private text in an allowed field. The desktop Plugins chooser starts with empty Runner/path selection and scans only on explicit Scan. Remote paths are labeled as paths on that Runner. Account/connection changes and observed selected Runner removal, OS or key changes clear results and stickily invalidate pending replies, even when the old binding returns; unrelated roster events preserve results. Rust compares current relay membership attestations and keys, not a universal monotonic ABA token. Secure discovery requires Linux openat2; unsupported platforms or secure root opens have no fallback.

## Managed skill library

`beans_agent::harness::skill_library::SkillLibrary` imports one explicitly caller-authorized selected source directory into a distinct, disjoint, existing Runner-owned library root. Linux requires `openat2`; unsupported platforms and kernels fail closed. Roots and every resource open reject symlinks and traversal; descriptor-relative operations prevent path replacement from redirecting access. The library root must belong to the effective user with mode 0700; its lifecycle operations serialize with an advisory descriptor lock. Other code running as that same user can defeat this ownership boundary and is not treated as isolated. Imports allow at most 1,024 entries, 256 regular files, directory depth four, 1 MiB per file and 16 MiB aggregate; special files and child mount crossings fail the whole import. A random opaque bundle ID names a version-1 manifest recording caller-supplied source host/path, flat metadata, declared license without license inference, import Unix time, file sizes and SHA-256 digests, and unsupported/advisory findings. Resources are copied but never interpreted or executed. Scanner labels confer no open authority. Private same-filesystem staging is fsynced before Linux no-replace atomic rename. Pre-publication failures expose no partial bundle; cleanup can leave hidden staging debris on I/O failure or crash. Publication is the commit point: a subsequent root fsync failure is returned as a durability warning with the committed manifest, not as a failed import. Uninstall accepts only an exact managed ID, validates its bounded manifest and complete copied tree including digests, and moves that copy to a private tomb before descriptor-relative deletion; it never deletes the selected source or unrelated files. Cleanup/root-fsync errors after tomb rename report incomplete cleanup or durability, not restored visibility. Imports are bounded reads, not coherent source snapshots, and do not prove hard-link provenance. Runtime, portability and activation acceptance remain separate.

Every recursive source directory and resource open resolves its full relative path from the pinned selected-root descriptor. Child descriptors retain expected directory identity only; they never become independent read authority. A detached or replaced child fails its root-relative reopen/identity check, so newly added files in a child moved outside the selected root cannot enter the managed copy. Enumeration is not a snapshot: a concurrent move can invalidate labels, but those labels still require a fresh selected-root-relative secure open.

`preview_source` uses the same pinned-root traversal without staging or publication and returns bounded directories, copied-byte SHA-256 inventory and advisory metadata. `import_approved` compares the actual staged inventory and metadata with that preview before publication; any mismatch rejects rather than publishing different bytes. Immediately before import rename or guarded uninstall tomb rename, the primitive obtains a caller-owned authority guard and retains it through rename and durability reporting. The existing explicitly authorized import and uninstall entry points retain their callable contracts.

## Explicit copy consumer

The CLI exposes only `skills.library.preview`, `skills.library.import` and `skills.library.uninstall` for inactive managed copies. All use version 1 and an explicit current desktop `runner_id`; existing signed requests authenticate remote actor and target. Preview additionally takes an absolute `root`. The Runner owns the fixed private `skill-library` directory under its configured account home; clients cannot supply a destination. Preview creates that fixed directory if absent but never stages or publishes a copy. Its reply contains source/destination, a bounded metadata/license/findings/count/byte summary and an opaque approval token valid for 300 seconds. At most 32 pending approvals exist in the process; expired and orphaned approvals are pruned. Tokens bind the App/account incarnation, current actor, selected Runner membership/key binding, selected source and exact digest inventory/metadata. Confirmed import takes only that token and consumes it before filesystem effects, including failed imports. Changed staged source rejects with `skill_library_source_changed`; no post-publication rollback substitutes for rejection. Confirmed uninstall takes only an exact managed ID and removes the validated owned copy, never the source. Import and uninstall are mutations, not read-only discovery or continuation verbs.

After asynchronous work, current authority is checked under retained lifecycle and state locks before copy/tomb publication and before returning results. Membership/key comparisons use current relay attestations, not a universal monotonic ABA generation. Rust and desktop independently decode closed, bounded reply DTOs; raw bodies/resources/hooks and filesystem errors are not returned. An authorized Runner can invent schema-valid summary text, so validation does not authenticate metadata provenance. Durability and private cleanup warnings describe committed visibility changes and never authorize automatic retries.

The existing desktop discovery sheet keeps Scan read-only and adds separate Preview copy, Confirm import and exact-ID Confirm removal actions. Nothing copies on mount, scan or selection. Confirmation shows Runner, exact source and fixed destination, declared license or unknown, resource counts/findings, expiry and copy-only/no-execution/no-grants disclosure. Cancel performs no mutation. The store and mounted sheet stickily invalidate pending replies and confirmations on observed account/connection or selected Runner removal/key/OS transitions, including away/back restoration; unrelated roster updates preserve confirmation. This explicit copy path supplies no activation, execution, hooks, grants, providers or automatic import. Signed Linux runtime, independent immutable review and full parent acceptance remain separate gates.
