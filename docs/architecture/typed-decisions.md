# Staged typed decisions

`decision` is a pure request, response and capability validator. Its current wire profile accepts pinned `jev-MAJOR.MINOR.PATCH` model ids and keyed Choice, Score and Noul questions. Choice accepts 1–255 options; Score accepts 2–10 ordered levels; Noul criteria are absent or exactly `false` and `true`. State and instructions accept text, objects or arrays. Choice option descriptions additionally accept null. These are this profile's structural rules, not verified capabilities of other models.

Responses must name the requested model and return exactly the requested question ids and types. Deserialize directly from raw JSON: duplicate keys in `answers`, `probabilities` or `legend` reject the response, including identical entries and escaped spellings of the same key. Parsing through an untyped JSON value first loses this evidence. Probabilities and confidence are finite and within [0,1]. Probability sums have an inclusive 0.01 tolerance plus 1e-9 floating-point representation slack; validation never clamps or normalizes. Choice selects a maximum-probability option (ties allowed). Score matches the requested legend, stays within level indices and agrees with the probability-weighted position within the same tolerance. Noul returns a finite probability of yes.

`DecisionCapabilities` carries optional support flags for each question type and optional question, option and level limits. Missing or null facts remain unknown; false means unsupported and zero is a known limit. `preflight_request` validates structure first, rejects known unsupported types or exceeded limits without truncation, and returns `Unverified` whenever a relevant fact is unknown. `Verified` means only that these supplied facts passed this local preflight; it proves no provider availability or permission.

`DecisionRejection` distinguishes model pin/match, shape, question identity/type, criteria bounds, unsupported capability, exceeded limit, probability/normalization, confidence, selected-choice, score and legend errors. Serde parsing rejects unknown question types and unknown question fields. No caller dispatches this module: transport authentication, retry hints, timeouts, cancellation, per-turn budgets, image/state limits, catalog persistence and cross-Device compatibility remain unimplemented. The validator has no fallback dispatch. Decisions cannot authorize actions. Decisions cannot widen tool or profile access. A future caller must use the explicitly configured default generative model for ordinary response work when a decision fails; this policy is not an implemented automatic fallback.
