# Website

The Windows download resolves both the staged `Lorca Setup <version>.exe` name and GitHub's normalized `Lorca.Setup.<version>.exe` asset name.

`web/` is the Beans site at `usebeans.app`, deployed on Vercel: TanStack Start (React, file routes under `web/src/routes`), Tailwind and shadcn/ui components, built with Vite and served by Vercel Functions through the Nitro Vite plugin (`nitro/vite`), with static assets on the Vercel CDN and Cloudflare DNS for the domain. The shared shell self-hosts Manrope, with system fallbacks. Its coral bean mark and lowercase wordmark share the Beans app identity; editable Bézier SVG masters, raster exports and generation prompts live in `design/brand/`. `scripts/export-brand-assets.cjs` renders website icons, favicons and PNG fallbacks from those masters. The header renders the full SVG logo in light and dark variants; the hero renders the SVG mark. The footer links static `/privacy.html` and `/support.html` pages, with `support@usebeans.app` as the contact address. The site loads no advertising or analytics script. The homepage contains a hero sculpture, a scripted interactive team preview, an asymmetric feature bento, provider marks, free-app pricing, comparison links, device privacy, setup and FAQ. The preview selects three sample tasks and reveals messages and review artefacts without connecting a provider or running tools. The site identifies Beans as free and separates provider subscription/API charges. Provider SVGs in `web/public/providers` come from Lobe Icons with its license; names identify supported connections. Social metadata uses the absolute URL of `web/public/brand/beans-social-v2.png`, a generated brand campaign image, with dimensions and Twitter image metadata. `/compare` and `/zh/compare` list comparisons with OpenBot, Grok Bot and Claude Code. Each detail route has localized copy, canonical and alternate links, a mechanism/cost table, primary-source links and a checked date; unknown products return 404. The shared footer links product sections, downloads, docs, source, releases, providers, comparisons, privacy and support. The product docs are at `/docs`: MDX under `web/content/docs` (`meta.json` orders the sidebar), compiled by the `fumadocsMdx` Vite plugin and loaded in `src/lib/source.ts`, in English at `/docs` and Chinese at `/zh/docs` (`bots.zh.mdx` beside `bots.mdx`, `meta.zh.json` beside `meta.json`; a page with no translation falls back to English), rendered by Fumadocs UI (`src/components/docs/page.tsx`, shared by the routes `docs/$.tsx` and `zh_/docs/$.tsx`) with the site's own color tokens (`fumadocs-ui/css/shadcn.css`) and the system's appearance, which a script in the root shell (`src/routes/__root.tsx`) keeps as `.dark` on `<html>`. `/api/search` is the Orama index built from the same source, one per language, with the Mandarin tokenizer for Chinese; `/docs/<page>.md`, `/llms.txt`, and `/llms-full.txt` serve the pages as Markdown, with the Chinese ones under `/zh`. The download page (`src/components/site/download.tsx`, at `/download` and `/zh/download`) links the Mac app's disk image from the Sparkle appcast, which the server reads on each request, and the Windows and Linux app's files from finalized stable `beans-v` releases that contain readiness and signature assets: the installer, the release's `install.sh` as a `curl … | sh` command, and the Debian packages. The build selects each platform's newest available client assets from the Beans GitHub releases API once (`src/lib/desktop-release.ts`, `define` in `web/vite.config.ts`, with `GITHUB_TOKEN` or `GH_TOKEN` when set), so a new desktop release reaches the page with the next deploy, and a release build that can't read it stops; the dev server warns and leaves those buttons disabled. Its CLI commands fetch `web/public/install-cli.sh` and `install-cli.ps1`, which `web/vercel.json` serves as UTF-8 text (see [Installing the CLI](runtime.md#installing-the-cli)). `/models/v1.json` and `/marketplace/v1.json` are the model catalog and the marketplace index every Device checks for a newer one: the `servedFiles` plugin in `web/vite.config.ts` writes `crates/models/catalog.json` and `crates/cli/marketplace/index.json`, minified, to `web/public/models/v1.json` and `web/public/marketplace/v1.json` (ignored by git) when the dev server or a build starts, and Vercel serves them as static files with an ETag, so a check is a 304 until the file changes. Deploy from the reviewed source checkout, since the site serves that checkout's files (see [Providers](providers.md) and [Marketplace](marketplace.md#the-index)). `bun run web` serves it locally on port 3000; `bun run web:deploy` runs `vercel --prod` from the repository root.

## Landing-page motion

The English and Chinese homepages share `MotionExperience` and `experience.css`. GSAP and ScrollTrigger load on the client to coordinate hero parallax, the interactive preview’s perspective transition, privacy orbit movement, bento assembly and setup entrances, reading progress and the final logo reveal. Native scrolling and section anchors remain available. Navigation to downloads and docs uses progressive browser View Transitions.

`BeanScene` lazily loads Three.js through `bean-webgl.ts`, extruding the editable SVG mark into a bevelled coral object with physical lighting. Pointer movement gently changes its orientation. The renderer caps pixel ratio at 1.5 and stops its animation frame loop offscreen, while the document is hidden, or when the visitor pauses motion. A Pause motion control also removes scroll animations. Reduced-motion preferences skip WebGL and scroll choreography, retain the SVG illustration and disable decorative loops. Failed WebGL initialization or context loss keeps the SVG fallback visible. Unmount disposes geometry, materials, the renderer, observers and listeners. The page’s content renders on the server before animation modules load; homepage head metadata preloads the self-hosted Manrope display font. Light-mode coral headline text uses a darker tone for large-text contrast.

The same WebGL frame loop drives the coral contour shader in `energy-field.ts`, with flowing highlights and pointer response behind the sculpture. CSS animates the orbit rings and the headline’s letters, with a plain accessible heading label. Intersection observers and document visibility pause these loops outside the viewport or hidden tab; the motion control and reduced-motion preference stop them too. Buttons have a hover sheen and moving arrow, feature rows draw an accent line on hover, and setup numbers highlight as their step enters view. Header, body and footer share responsive gutters; section spacing contracts on phones, and the closing illustration has a bounded height.

`WorkExamples` selects launch planning, feature building and brief writing scenarios. A visible, unpaused preview reveals its scripted team messages on a timer and offers replay. Reduced motion shows the complete transcript. The feature bento carries concrete illustrative conversations, file changes, memory notes, a routine schedule, permission prompts and device sync. Its panels assemble with scroll progress, and task details animate while visible. The relay diagram assembles its nodes and connectors with scroll progress; its computer, relay and phone run a staggered encryption, forwarding and decryption illustration while visible. These examples share the page’s pause, visibility and reduced-motion controls.
