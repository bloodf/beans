中继在你的设备之间存储并转发加密的数据块。只有一台设备时完全不需要中继。要配对第二台电脑或手机，才需要一个。

因为一切都[在上传前加密](/zh/docs/security)，你对中继的信任只需要到“它能保持在线”为止。

## 让 Beans 使用某个中继

在第一台设备上设置 **设置 › 高级 › 中继 URL**，或者为命令行设置 `BEANS_RELAY_URL` 环境变量。之后配对的设备会从配对码里得知这个地址。

账户路由（包括注册、验证、配对信箱和同步）要求唯一且有效的 `Beans-Protocol: 5`、`Beans-Format: beans-v2`。协议下限不能低于 5。旧格式设备不兼容；不存在自动迁移或生产部署。SQLite 在打开前要求 `BNR2` 应用标识 `0x424E5232`；Postgres 的 `beans_storage_format` 必须只有一行 `beans-v2`，且只能在真正空的 schema 内初始化。未标记的已有数据会在 DDL/恢复之前被拒绝，保持不变。

## 限制

- 每个附件最大 **100 MiB**。消息和其他数据，加密后每条最大 **4 MiB**。
- 一个账户如果整整一年没有任何活动（没有设备连接，也没有任何同步），会从中继上删除。你的设备仍保留本地数据，第一台重新连接的设备会重新注册这个账户。

## 自己运行中继

Beans 的中继就是你可以自己运行的同一个程序：单个可执行文件 `beans-relay`，内置 SQLite。之后你的设备就改为通过你的服务器同步。

```bash
beans-relay --bind 0.0.0.0:8787 --db beans-relay.db
```

用 Caddy 或 nginx 这类反向代理为它加上 HTTPS（WebSocket 升级必须能通过），并加上 `--trust-proxy`，让限流看到真实的客户端地址。

### 让 Beans 使用它

在第一台设备上、配对其他设备之前，设置 **设置 › 高级 › 中继 URL**；只有[命令行](/zh/docs/cli)的电脑则设置 `BEANS_RELAY_URL` 环境变量。之后配对的设备会从配对码里得知这个地址。从你的中继[作为链接分享](/zh/docs/templates)的智能体，链接里会带上中继地址，usebeans.app 会从那里打开它。

### 选项

| 选项 | 作用 |
| --- | --- |
| `--bind` | 监听的地址和端口。 |
| `--db` | SQLite 文件路径，或 `postgres://` URL。 |
| `BEANS_RELAY_SECRET` | 用来签发会话令牌。设置它，令牌才能在重启后继续有效。 |
| `--quota-bytes` | 每个身份的存储上限，默认 5 GiB。`0` 表示不限。 |
| `--concurrent-uploads` | 同时处理的超过 1 MiB 的附件数量（默认 3），用来限制附件占用的内存。 |
| `--files-dir` | 附件密文存放的位置。默认是数据库旁边的一个文件夹。 |
| `--s3-bucket`、`--s3-endpoint` | 改为把附件存到 S3、R2 或 MinIO。 |
| `--min-protocol` | 拒绝使用更旧中继协议的 Beans 版本，这些版本的应用会提示更新。 |
| `--inactive-days` | 账户在这么多天内没有任何活动就会被删除（默认 365，`0` 表示永不删除）。各设备上的本地数据不受影响。 |
| `--ip-per-minute`、`--identity-per-second` | 限流。 |
| `BEANS_RELAY_METRICS_TOKEN` | 设置后，携带此 Bearer 令牌即可从 `GET /metrics` 读取 Prometheus 格式的指标。 |

### pull request 关注与 Webhook

Beans 的中继托管了[关注 pull request](/zh/docs/routines#关注-pull-request)和[例行任务的 Webhook](/zh/docs/routines#webhook)的接收端。你自己的中继也可以：`BEANS_RELAY_PUBLIC_URL` 设为中继自己的公网地址，就会开启 Webhook（`<地址>/webhooks/<id>`）；再用 [`crates/relay/github-app.json`](https://github.com/bloodf/beans/blob/main/crates/relay/github-app.json) 注册一个你自己的 GitHub 应用，把其中的地址改成你中继的地址（`/webhooks/github` 和 `/webhooks/github/callback`），并设置 `BEANS_RELAY_GITHUB_APP_ID`、`BEANS_RELAY_GITHUB_APP_SLUG`、`BEANS_RELAY_GITHUB_CLIENT_ID`、`BEANS_RELAY_GITHUB_CLIENT_SECRET`、`BEANS_RELAY_GITHUB_WEBHOOK_SECRET` 和 `BEANS_RELAY_GITHUB_PRIVATE_KEY`，就会开启关注。

没有这些设置时，这类例行任务会显示 **你的网关**，事件要通过你在自己电脑上运行的[网关](/zh/docs/events)送达。智能体会告诉你例行任务的订阅 id；用 `beans events route <id> route.json` 导出它的路由，然后：

- 关注 pull request：用 `--github-secret-file <secret> --routine` 运行网关，并在仓库里添加一个 webhook：填你的公网地址、JSON 格式、同一个密钥，事件选 Pull requests、Pull request reviews、Pull request review comments 和 threads、Issue comments、Check runs、Check suites、Statuses 和 Workflow runs。
- Webhook：用 `--webhook-key-file <key>` 运行网关（至少 32 个字符的随机密钥）。它监听 `127.0.0.1:8984/hook`，以 `Authorization: Bearer <key>` 接收密钥。

### Postgres

使用 `postgres://` URL，可以让多个中继进程共用一个数据库，实现无间断部署。它们必须共用 `BEANS_RELAY_SECRET`，并把附件存在 S3 兼容的存储桶里。

### 推送通知

要给手机应用发推送，需要给中继配置 APNs 密钥（`--apns-key`、`--apns-key-id`、`--apns-team-id`）或 Firebase 服务账号（`--fcm-service-account`）。每个密钥既可以是文件路径，也可以直接是密钥内容，所以在没有磁盘存放文件的环境里，可以用 `BEANS_RELAY_APNS_KEY` 和 `BEANS_RELAY_FCM_SERVICE_ACCOUNT` 变量直接传入。不配置的话其他功能照常，只是手机收不到推送。

### 监控

设置 `BEANS_RELAY_METRICS_TOKEN` 后，抓取方携带该 Bearer 令牌访问 `GET /metrics`，即可得到 Prometheus 文本格式的指标：身份和设备数量、各类数据块的数量与字节数、打开的同步连接、按路由和状态码统计的请求、被限流的请求、推送的成功与失败，以及清理任务删除的内容。中继无法读取自己存储的内容，所以这些数字就是全部可观察的信息。

### 模型目录和市场

各设备会到 beans.app 检查有没有更新的模型目录和市场。要用你自己托管的版本，让[命令行](/zh/docs/cli)指向它们：

| 变量 | 设置什么 |
| --- | --- |
| `BEANS_MODELS_URL` | Beans 检查新模型目录的地址。默认 `https://usebeans.app/models/v1.json`。 |
| `BEANS_MARKETPLACE_URL` | Beans 检查新市场的地址。默认 `https://usebeans.app/marketplace/v1.json`。 |
